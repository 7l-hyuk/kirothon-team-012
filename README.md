# 신고메이트

길에서 불법주정차나 쓰레기 무단투기를 보고도 "이게 신고가 되나, 어디에 하나" 몰라서 지나치는 사람에게, 사진 한 장으로 신고 가능 여부를 알려 주고 반려되지 않게 증거 준비와 접수 과정을 끝까지 안내하는 AI 어시스턴스입니다.

## 1. 문제 정의

### 대상 사용자
출퇴근길과 동네에서 불법주정차, 쓰레기 무단투기, 불법 광고물, 시설물 파손을 자주 보지만 신고를 한 번도 해 본 적 없는 사람.

### 문제 상황
인도에 올라온 차 때문에 차도로 돌아가거나 골목에 쌓인 쓰레기를 볼 때(상황), 신고하고 싶어도 네 가지를 몰라서 포기합니다(불편).

1. 이게 신고가 되는 건지
2. 어느 기관에 해야 하는지
3. 어느 사이트나 앱으로 해야 하는지
4. 어떤 자료를 내야 하는지

용기를 내서 신고해도 사진 요건을 못 맞춰 반려되고, 그 뒤로는 다시 신고하지 않게 됩니다.

### 기존 방식과 한계
| 기존 방식 | 한계 |
|---|---|
| 포털·블로그 검색 | 지자체마다 기준이 달라 글마다 내용이 다르고, 내 상황에 맞는지 스스로 판단해야 합니다 |
| 안전신문고 앱에 바로 접수 | 신고 유형을 직접 골라야 하고, 사진이 요건에 맞는지는 접수 후 담당자가 판단합니다. 미달이면 며칠 뒤 반려 통보를 받습니다 |
| 120 등 전화 문의 | 현장에서 통화하며 설명해야 하고, 사진 요건은 결국 직접 맞춰야 합니다 |

### 근거
- 2022년 안전신문고 신고 565만 4,076건 중 불법주정차가 343만 1,971건(60.7%)입니다. 가장 많이 신고되는 생활 불편입니다. ([세계일보, 행정안전부 자료 인용](https://www.segye.com/newsView/20240620516628))
- 불법주정차 주민신고는 요건이 까다롭습니다. 같은 위치·같은 방향에서 1분 이상 간격으로 찍은 사진 2장이 필요하고, 두 장 모두 번호판이 식별되고 주변 배경이 포함되어야 합니다. 정면 1장과 측면 1장은 같은 위치로 인정되지 않습니다. ([구리시](https://www.guri.go.kr/www/sub.do?key=743), [금천구](https://geumcheon.go.kr/portal/contents.do?key=3431))
- 신고 대상은 6대 금지구역(소화전, 교차로 모퉁이, 버스정류소, 횡단보도, 어린이보호구역, 인도)으로 한정되고, 촬영 간격은 구역에 따라 1분과 5분으로 나뉩니다. ([수원시](https://www.suwon.go.kr/sw-www/deptHome/dep_traffic/traffic02/traffic02_02_19.jsp))
- 공공데이터포털의 불법주정차 신고 데이터에는 "불수용 사유" 항목이 따로 있습니다. 요건 미달 반려가 반복해서 일어난다는 뜻입니다. ([공공데이터포털](https://www.data.go.kr/data/15152654/fileData.do))

### 목표
신고를 처음 해 보는 사람도 사진 한 장만 올리면, 신고 가능 여부 판단부터 증거 준비, 접수 문구 작성까지 한 번에 끝내고 반려 없이 접수하게 만듭니다.

## 3. 사용 시나리오

1. 퇴근길에 인도 위에 주차된 차와 전봇대 아래 쓰레기 더미를 보고, 신고메이트에 사진 1장을 올립니다.
2. AI가 "불법주정차(인도), 쓰레기 무단투기 2건을 신고할 수 있어요"라고 알려 주고, 사용자는 두 항목을 모두 선택합니다.
3. 쓰레기 건에 위치가 보이는 사진이 1장 더 필요하다는 안내를 받습니다. 처음 찍은 사진은 도로명 표지판이 잘려 "두세 걸음 물러나 건물 간판이 함께 나오게 찍어 주세요"라는 안내를 받고, 다시 찍어 통과합니다.
4. 안전신문고 접속, 메뉴 선택, 사진 첨부 순서로 한 단계씩 따라 하고, AI가 써 준 신고 문구를 복사해 붙여 넣어 접수합니다.
5. 불법주정차 건으로 넘어갑니다. 로그인과 위치 입력은 이미 했으므로 건너뛰고, 차량 뒤쪽에서 번호판과 인도 경계석이 함께 나오게 찍는 방법을 안내받은 뒤 1분 타이머에 맞춰 2장을 찍어 접수합니다.
6. 두 건이 "내 신고"에 기록되고, 다른 사용자가 볼 수 있는 사례 글로 공유할지 선택합니다.

신고 대상이 아닌 경우도 안내합니다. 아파트 지하주차장 이중주차 사진을 올리면 "사유지라 주민신고 대상이 아니에요"라고 이유를 설명하고 관리사무소 문의를 권합니다.

## 4. 기대 효과

| 지표 | 지금 | 신고메이트 사용 후 |
|---|---|---|
| 신고 방법을 찾는 데 걸리는 시간 | 검색으로 10분 이상 | 1분 이내 |
| 불법주정차 사진 요건 미달을 알게 되는 시점 | 접수 며칠 뒤 반려 통보 | 접수 전 사전 점검에서 즉시 |
| 같은 장소 2건 신고 시 사진 촬영 횟수 | 건마다 새로 촬영 | 겹치는 사진은 1번만 촬영 |

"지금"의 10분은 팀의 추정값입니다.

## 5. 차별점

안전신문고는 신고를 "접수"하는 곳이고, 신고메이트는 접수 **전** 단계를 맡습니다. 둘은 경쟁하지 않고 이어집니다.

| | 안전신문고 | 신고메이트 |
|---|---|---|
| 신고 가능 여부 판단 | 사용자가 직접 | AI가 사진과 글을 보고 판단하고 이유를 설명 |
| 증거 요건 확인 | 접수 후 담당자가 판단, 미달이면 반려 | 접수 전에 AI가 검수하고 재촬영 방법 안내 |
| 신고 문구 | 사용자가 직접 작성 | AI가 대신 작성 |
| 여러 건 동시 신고 | 건마다 처음부터 | 이미 찍은 사진과 끝낸 단계는 재사용 |
| 다른 사람의 신고 경험 | 볼 수 없음 | 사례 글로 공유 |

일반 AI 챗봇과도 다릅니다. 챗봇은 신고 방법을 글로 설명하는 데서 끝나지만, 신고메이트는 사진을 직접 검수하고 접수가 끝날 때까지 단계를 이어 갑니다.

## 6. 설치와 실행

### 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 백엔드 | Python 3.13, FastAPI, uv |
| 프론트엔드 | React, Vite, TypeScript, Tailwind CSS |
| AI | Claude Opus 5.5 (`claude-opus-5-5`, Anthropic Python SDK), 사진 분석과 신고 문구 작성 |
| 데이터 | PostgreSQL + SQLModel, 신고 절차 데이터는 `backend/data/*.json` |
| 사진 저장 | Amazon S3 비공개 버킷, 조회는 presigned URL |
| 사용자 구분 | 로그인 없이 익명 기기 ID |
| 배포 | AWS EC2 1대에 Docker Compose (FastAPI + PostgreSQL), HTTPS는 CloudFront |

### 실행 방법

Python 3.13 이상, [uv](https://docs.astral.sh/uv/), Node.js 24, Docker가 필요합니다.

```bash
# 1. 의존성 설치
cd backend && uv sync && cd ..
cd frontend && npm install && cd ..

# 2. 환경변수 설정 (backend/.env, 커밋하지 않습니다)
echo "ANTHROPIC_API_KEY=발급받은_키" > backend/.env

# 3. 로컬 DB 실행 (PostgreSQL)
docker compose up -d db

# 4. 실행 (터미널 2개)
cd backend && uv run uvicorn app.main:app --reload --port 8000
cd frontend && npm run dev
```

브라우저에서 http://localhost:5173 을 엽니다. 프론트의 `/api` 요청은 Vite 프록시가 백엔드(8000번 포트)로 넘깁니다.

`S3_BUCKET`을 설정하지 않으면 사진은 로컬 `backend/uploads/`에 저장됩니다.

### 배포 구성

```
사용자 ──HTTPS──> CloudFront ──HTTP──> EC2 (Docker Compose)
                                        ├─ app: FastAPI + React 빌드 결과물
                                        └─ db: PostgreSQL
                                        app ──> S3 (사진), Claude API
```

서버에서는 `docker compose up -d --build` 한 번으로 앱과 DB를 함께 띄웁니다. S3 접근 권한은 EC2의 IAM 역할로 주고, 액세스 키는 서버에 두지 않습니다.
