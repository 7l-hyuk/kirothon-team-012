# 제품 개요: 신고메이트

## 목적
길에서 불법주정차, 쓰레기 무단투기, 불법 광고물, 시설물 파손을 보고도 "이게 신고가 되나, 어디에 하나" 몰라서 지나치는 사람에게, 사진 한 장이나 글 한 줄로 신고 가능 여부를 알려 주고 반려되지 않게 증거 준비와 접수 과정을 끝까지 안내하는 모바일 웹 앱입니다. 안전신문고는 "접수"를 맡고, 신고메이트는 접수 **전** 단계를 맡습니다.

## 대상 사용자
신고를 한 번도 해 본 적 없는 사람. 출퇴근길과 동네에서 위 상황을 자주 보지만 방법을 몰라 포기합니다.

## 해결하는 불편
1. 이게 신고가 되는 건지 모름
2. 어느 기관에 해야 하는지 모름
3. 어느 사이트나 앱으로 해야 하는지 모름
4. 어떤 자료를 내야 하는지 모르고, 사진 요건 미달로 반려됨

## 다루는 범위
다루는 유형은 아래 4개뿐이고, 모두 **안전신문고**로 접수합니다.

| 구분 | 유형 | 접수 메뉴 |
|---|---|---|
| 신고 | 불법주정차 (6대 금지구역: 소화전, 교차로 모퉁이, 버스정류소, 횡단보도, 어린이보호구역, 인도) | 안전신문고 > 불법주정차 |
| 민원 | 쓰레기 무단투기 | 안전신문고 > 생활불편 |
| 민원 | 불법 광고물 (전단지, 현수막) | 안전신문고 > 생활불편 |
| 민원 | 도로·시설물 파손 (보도블록, 가로등 등) | 안전신문고 > 안전신고 |

메뉴 경로는 안전신문고 앱에서 확인되기 전까지 `[확인 필요]`입니다. 최종 값은 `backend/data/*.json`이 기준입니다.

## 다루지 않는 범위
- 위 4개 외의 유형. 입력되면 "아직 안내하지 못하는 유형이에요"라고 알리고 **멈춥니다**. 다른 기관이나 방법을 추측해 안내하지 않습니다.
- 대리 접수. 접수는 사용자가 안전신문고에서 직접 합니다.
- 안전신문고와의 연동. 처리 결과(수용/불수용)는 사용자가 직접 입력합니다.
- 긴급 상황. 사람이 다쳤거나 위험이 진행 중이면 112/119 안내 배너를 띄웁니다(기획서 기준. 구현 우선순위는 낮음. 지금 화면에서는 뺐습니다).
- 로그인과 회원 관리.

## 핵심 기능과 구현 우선순위
마감은 2026-11-14(토) 18:00입니다. 위에서부터 구현하고, 앞 단계가 끝나기 전에 뒤 단계를 시작하지 않습니다.

1. 상황 분석과 항목 선택: 사진이나 글을 받아 신고·민원 가능한 항목을 체크박스로 보여 주고, 안 되는 경우는 이유를 설명합니다.
2. 증거 검수와 불법주정차 사전 점검·타이머
3. 단계별 접수 안내와 문구 대필
4. 내 신고 (준비 중 / 접수 완료 / 처리 완료)
5. 사례 공유

여러 건을 이어서 신고할 때 이미 올린 사진과 끝낸 단계(로그인, 위치)는 건너뜁니다. 이 기능은 (3)에 포함해서 구현합니다.

## 화면 구조
모바일 웹, 세로 390px 기준. 하단 탭은 없습니다. **S0 홈**이 유일한 시작점이고, 세 기능을 카드 하나씩으로 엽니다: **신고하기**(큰 카드) / **신고 조회** / **신고 사례**. 하위 화면은 상단의 뒤로 가기·홈 아이콘으로 이동합니다. 자세한 흐름은 `.kiro/specs/frontend-redesign/requirements.md`의 "UI 흐름"이 기준입니다.

```
S0 홈 ─ 신고하기 ─> S1 ─> S2~S8 (대화) ─> S9 ─> 신고 조회 / 사례 공유(S14) / 홈
      ─ 신고 조회 ─> S10 ─> S11 ─> S14
      ─ 신고 사례 ─> S12 ─> S13 ─> "나도 비슷한 상황이에요" ─> S1
```

신고하기는 대화 화면 안에 카드(항목 선택, 증거, 단계 안내)가 끼워지는 형태이고, 상단에 번호 원 5개의 진행 표시(상황 입력 → 항목 선택 → 증거 준비 → 접수 안내 → 완료)가 S1부터 S9까지 이어집니다.

디자인 톤은 S0 홈과 같은 남색 전통문양(청해파, 창살, 구름)입니다. 마스코트는 쓰지 않습니다. 화면에는 보조 설명 문구를 붙이지 않고 깔끔하게 둡니다. 기준 화면은 아이폰 14(390×844)이고 다른 비율에도 맞춰 늘고 줄어듭니다.

| 화면 | 요약 |
|---|---|
| S0 홈 | 남색 문양 배경, "신고메이트" 제목, 카드 3개(신고하기 / 신고 조회 / 신고 사례) |
| S1 상황 입력 | "무슨 불편을 겪으셨나요?"(한 줄), 사진·텍스트 입력, 다루는 4개 유형 카드(누르면 예시 입력), 진행 중 건이 있으면 "이어서 하기" 카드 |
| S2 분석 중 | 썸네일과 말풍선, 진행 문구가 순서대로 바뀜 |
| S3 분석 결과 | 상황 요약, 신고/민원 체크박스 카드, 신고가 어려운 항목, 항목별 근거. 신고 불가 상태(예: 사유지)도 표시 |
| S4 증거 안내 | 항목별 필요한 장면 체크리스트. 이미 올린 사진으로 충족된 장면은 완료 표시 |
| S5 증거 검수 결과 | 장면별 충분 / 불충분 / 판단 불가 |
| S6 불법주정차 | S6-1 사전 점검(금지구역, 번호판, 배경), S6-2 본촬영 가이드, S6-3 1분 타이머 |
| S7 접수 안내 | 한 화면에 한 단계. "했어요"로 넘어감. 대필 문구 카드에 "글 복사", "다시 써 줘"(더 짧게 / 더 정중하게) |
| S8 다음 항목 | 끝낸 단계를 건너뛰고 다음 건으로 이어감 |
| S9 완료 | 건별 요약(접수번호가 있으면 복사), 공유 권유, "신고 조회에서 보기", "홈으로" |
| S10 신고 조회 | 필터 칩(전체 / 준비 중 / 접수 완료 / 처리 완료), 목록, 빈 상태에 "신고하러 가기" |
| S11 신고 조회 상세 | 상태 타임라인, 사진, 제출 문구, 접수번호, 처리 결과 직접 입력, 사례로 공유 |
| S12 신고 사례 | 유형 필터, 카드(대표 사진, 제목, 유형·결과 배지, 구 단위 지역, 도움돼요 수), 끝에 "신고하러 가기" |
| S13 사례 상세 | 상황 / 준비한 사진 / 접수 방법 / 결과 / 팁. "도움돼요", "나도 비슷한 상황이에요"(같은 유형으로 S1 시작) |
| S14 공유 동의 | 공유될 내용 미리보기와 동의 체크박스. 아래 "사례 공유와 개인정보" 참고 |

## 불법주정차 흐름 (사전 점검 → 본촬영)
- 앱에서는 사용자가 올린 사진으로 **금지구역 여부, 번호판 식별, 주변 배경 포함**을 미리 판정합니다(S6-1).
- 본촬영은 안전신문고 앱에서 합니다. **같은 위치, 같은 방향**으로 1분 간격 2장을 찍도록 타이머와 함께 안내합니다(S6-2, S6-3). 앞에서 1장, 옆에서 1장은 반려된다고 알립니다.
- 안전신문고 앱 안에서 찍은 사진만 인정되는지, 어린이보호구역 등 일부 구역이 5분 간격인지는 `[확인 필요]`입니다. 타이머 아래에 "어린이보호구역은 5분 간격이 필요할 수 있어요"를 보조 문구로 둡니다.

## 증거 검수 상태
세 가지만 씁니다.

| 상태 | 색 | 규칙 |
|---|---|---|
| 충분 | 초록 + 체크 아이콘 | 왜 충분한지 한 줄 |
| 불충분 | 주황 + 경고 아이콘 + 재촬영 버튼 | **무엇이 부족한지**와 **어떻게 다시 찍을지**를 반드시 함께 씁니다 |
| 판단 불가 | 회색 | 원인(예: 너무 어두움)과 다시 찍는 방법 |

상태 색은 이 세 가지로 통일합니다. 색만으로 구분하지 않고 아이콘과 글자를 함께 씁니다. 신고/민원 배지도 색과 글자를 함께 씁니다.

## 문구 톤
- 해요체, 짧게. 관공서 말투가 아니라 "옆에서 알려 주는 친구" 느낌.
- 화면 하나에 질문 하나. 한 번에 한 가지만 묻습니다.
- 예: "사진이 너무 어두워요. 플래시를 켜고 다시 찍어 주세요."
- AI가 만든 사용자용 문구도 같은 톤을 따릅니다. 프롬프트에 명시합니다.

## AI 판정 고지
AI 판정이 나오는 모든 화면(S3, S5, S6-1)에 "참고용 안내이며 최종 판단은 담당 기관이 합니다"를 작게 넣습니다.

## 사례 공유와 개인정보
- 공유는 사용자가 동의한 건만, 동의 화면(S14)을 거쳐야 합니다. 내 신고 상세에서 언제든 내릴 수 있습니다.
- 공유 글: 주소는 **구 단위**, 날짜는 **월 단위**로 줄이고, **접수번호는 제외**합니다. 이름·연락처도 넣지 않습니다.
- **사진은 원본 그대로 공개됩니다.** 번호판·얼굴 가리기는 시간이 남으면 추가하는 후순위 기능입니다. 따라서 S14 미리보기에는 "사진은 가리지 않고 그대로 공개돼요"를 분명히 적습니다. 기획서의 "번호판·얼굴 가림" 표기는 이 결정으로 대체됩니다.
- 사례 초기 데이터는 예시 3~4건(DB seed)입니다.
