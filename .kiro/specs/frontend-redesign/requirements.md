# 요구사항: 프론트 화면 톤 통일 (홈 화면 기준 리디자인)

이미 만든 홈 화면(`/`, 남색 전통문양)과 같은 톤으로 나머지 화면을 다시 그린다. 참고 자료는 `~/Downloads/신고메이트 민원 앱 UI 콘셉트.png`(4화면: 홈, 신고 유형 선택, 단계 진행, 접수 완료)다. 레퍼런스는 배경·아이콘·카드·버튼의 **시각 스타일**만 가져오고, 화면 구성과 흐름은 지금 목업(`design/ShingoMateApp.dc.html`, `frontend/src/screens/`)과 `.kiro/steering/product.md`를 따른다. 크기와 배치는 필요하면 바꾼다.

동작(상태 전이, 가짜 데이터 흐름)과 백엔드 연동은 바꾸지 않는다. 연동은 별도 Spec(`frontend-api-integration`)에서 한다. 단, 화면 사이의 **이동 흐름**은 아래 "UI 흐름"대로 다시 짠다.

## UI 흐름 (재설계)
구현할 기능은 크게 세 가지다: **신고하기**(상황 입력부터 접수까지), **신고 조회**(내 신고 내역과 처리 결과), **신고 사례**(다른 사람의 공유 사례). 기존 목업은 이 셋을 하단 탭 3개로 나눴고, 새 홈(S0)은 메뉴 카드(신고하기, 신고 조회, 도움말)로 시작해 두 화면이 모두 "첫 화면" 역할을 하며 부딪혔다. 또 새 홈에는 사례로 가는 길이 없었다.

S0을 유일한 시작점으로 두고, 세 기능을 S0의 카드 세 개에 하나씩 연결한다. 도움말 카드는 **신고 사례** 카드로 바꾼다. 세 기능은 서로 이어지도록 교차 링크를 둔다.

```
S0 홈 (/)
├─ [큰 카드] 신고하기 ─> S1 상황 입력 (/report) ─> 신고 대화 (/chat: S2~S8) ─> S9 완료 (/done)
│                        [단계 표시 1~5가 S1부터 S9까지 이어짐]                  ├─ 신고 조회에서 보기 ─> S10
│                                                                                ├─ 사례로 공유 ─> S14 ─> S12
│                                                                                └─ 홈으로 ─> S0
├─ [작은 카드] 신고 조회 ─> S10 신고 조회 (/mine) ─> S11 상세 (/mine/:id) ─> 사례로 공유 ─> S14 ─> S12
│
└─ [작은 카드] 신고 사례 ─> S12 사례 목록 (/cases) ─> S13 사례 상세 (/cases/:id)
                                                       └─ 나도 비슷한 상황이에요 ─> S1
```

- 시스템은 하단 탭을 없애고, 모든 하위 화면 상단의 뒤로 가기·홈 아이콘으로 이동해야 한다.
- S0의 작은 카드 두 개는 "신고 조회"(`/mine`)와 "신고 사례"(`/cases`)여야 한다.
- 뒤로 가기는 위 트리의 부모 화면으로 가야 한다. (S1 → S0, S10 → S0, S12 → S0, S13 → S12, S11 → S10, 신고 대화 → S1)
- 홈 아이콘은 진행 중인 대기·타이머를 정리하고 S0으로 가야 한다.
- 단계 표시(상황 입력 → 항목 선택 → 증거 준비 → 접수 안내 → 완료)는 S1에서 1단계로 시작해 S9에서 모두 끝난 상태로 보여야 한다.
- S9은 "신고 조회에서 보기"와 "홈으로" 버튼을 둬야 한다.
- S10의 빈 상태와 S12의 목록 아래에는 S1로 가는 "신고하러 가기" 버튼을 둬야 한다. 세 기능 중 어디서 시작해도 신고하기로 이어져야 한다.
- 화면 제목은 홈 카드 이름과 같아야 한다. S1·신고 대화는 "신고하기", S10은 "신고 조회", S12는 "신고 사례".
- 도움말 화면은 만들지 않는다.

## 사용자 스토리
1. 사용자로서, 홈에서 신고하기를 누른 뒤에도 같은 앱이라고 느낄 수 있게 색, 문양, 카드 모양이 이어지길 원한다.
2. 처음 신고하는 사용자로서, 지금 몇 단계 중 어디에 있는지 숫자 단계 표시로 한눈에 알고 싶다.
3. 사용자로서, 글자 기호(‹ › ✓) 대신 알아보기 쉬운 아이콘과 큰 터치 영역을 원한다.
4. 심사위원으로서, 데모 영상의 모든 화면이 한 디자인으로 보이길 원한다.

## 인수 조건 (EARS)

### 디자인 토큰
- 시스템은 색, 모서리, 그림자 값을 `styles/tokens.css` 한 곳에 정의하고, 화면 코드와 `landing.css`는 이 토큰만 써야 한다.
- 시스템은 한지 크림(`#f7f3ea`)과 금색 포인트를 쓰지 않고, 홈 화면의 남색 계열(주색 남색, 글자 먹남색, 연한 청회색 바탕, 흰 카드)로 바꿔야 한다.
- 증거 상태 색은 충분(초록), 불충분(주황), 판단 불가(회색) 세 가지를 유지하고, 색만으로 구분하지 않고 아이콘과 글자를 함께 표시해야 한다. (`product.md` 규칙)

### 배경과 문양
- 홈이 아닌 화면은 연한 바탕 위에 청해파 물결을 화면 아래쪽, 오른쪽 위에 옅게 깔아야 한다. (레퍼런스 2~4번 화면)
- 문양은 장식이므로 `aria-hidden`이고, 글자와 버튼 뒤에 깔려 대비와 터치를 방해하지 않아야 한다.
- 문양은 SVG 코드로 그리고, 외부 이미지 파일을 추가하지 않아야 한다.

### 공통 부품
- 하위 화면(S11, S13, S14, 신고 대화)의 상단은 왼쪽 뒤로 가기 아이콘, 가운데 제목, 오른쪽 홈 아이콘으로 구성해야 한다. 홈 아이콘은 `/`로 이동해야 한다.
- 버튼은 주 버튼(남색 채움), 보조 버튼(남색 테두리), 약한 버튼(연한 바탕) 세 종류로 통일해야 한다.
- 카드는 흰 바탕, 큰 모서리(16px 이상), 옅은 그림자로 통일하고, 목록형 카드는 왼쪽 아이콘, 제목·설명, 오른쪽 화살표 구성을 써야 한다.
- 시스템은 화면에 쓰인 글자 기호 아이콘(‹, ›, ✓, ＋)을 SVG 선 아이콘으로 바꿔야 한다.
- 모든 터치 대상은 44×44px 이상이어야 한다.

### 화면별
- S1 상황 입력은 큰 제목("무슨 불편을 겪으셨나요?")과 입력 카드를 두고, 예시 칩 대신 다루는 4개 유형(불법주정차, 쓰레기 무단투기, 불법 광고물, 시설물 파손)을 아이콘 카드 2×2로 보여 줘야 한다. 카드를 누르면 그 유형의 일반 문장만 입력창에 채워져야 한다(사진은 넣지 않음. `.kiro/specs/analysis-prompt/` 참고).
- S1은 "이어서 하기" 카드를 유지해야 한다.
- 신고 대화 상단의 진행 표시줄은 5단계(상황 입력 → 항목 선택 → 증거 준비 → 접수 안내 → 완료)를 번호 원으로 보여 주고, 끝난 단계는 체크, 현재 단계는 남색 채움과 단계 이름으로 표시해야 한다.
- 신고 대화의 말풍선과 카드(항목 선택, 증거, 단계 안내)는 새 카드 스타일을 써야 한다.
- S9 완료는 가운데 큰 체크 원, 제목, 건별 요약 카드를 두고, 접수번호가 있으면 "복사" 버튼을 보여 줘야 한다. 접수번호가 없으면 복사 버튼을 숨겨야 한다.
- 타이머는 남색 원형 진행 표시를 써야 한다.
- S10, S12의 필터 칩과 목록은 새 카드 스타일을 써야 한다.

### 바꾸지 않는 것
- 상태 값, 문구 내용은 바꾸지 않아야 한다. 예외는 S1 예시 칩 → 유형 카드, 위 "UI 흐름"의 이동 경로와 화면 제목, S0의 "도움말" 카드 → "신고 사례" 카드다.
- AI 판정 고지("참고용 안내이며 최종 판단은 담당 기관이 합니다")는 S3, S5, S6-1에 그대로 있어야 한다.
- 레퍼런스의 "신고 유형을 사용자가 고르는 흐름", "행정·복지 민원" 같은 범위 밖 유형은 넣지 않아야 한다.

### 화면 크기
- 시스템은 아이폰 14(390×844)를 기준으로 그리고, 다른 비율에서도 배치가 깨지지 않아야 한다.
- 폭 600px 미만(휴대폰)에서는 화면 전체를 채우고, 노치와 홈 바 영역(safe-area)을 피해야 한다.
- 폭 600px 이상에서는 390×844 틀을 가운데 두고, 창이 작으면 틀 전체를 같은 비율로 줄여야 한다.
- 세로 길이가 다른 화면에서는 S0의 문양 영역과 위 여백이 늘고 줄어야 하고, 글자와 버튼 크기는 유지해야 한다.

### 문구
- 화면에는 제목, 입력, 버튼, 필수 고지만 두고 보조 설명 문구를 붙이지 않아야 한다. (예: "신고가 안 되는 경우도 알려 드려요", 112·119 안내, 목록 위 설명 줄)
- S1 제목 "무슨 불편을 겪으셨나요?"는 한 줄로 보여야 한다.
- AI 판정 고지와 공유 동의 화면의 개인정보 안내는 필수 고지라 유지한다.

### 움직임과 겹침
- 화면이 바뀌거나 대화에 새 말풍선·카드가 생기면, 시스템은 0.3초 이내의 짧은 등장 효과를 보여 줘야 한다.
- 사용자가 기기에서 움직임 줄이기(`prefers-reduced-motion`)를 켰으면, 시스템은 등장·맥박 효과를 끄고 바로 보여 줘야 한다.
- 토스트는 하단 고정 버튼 줄이나 홈 바 영역과 겹치지 않아야 한다.
- 한 카드 안에 상단 단계 표시와 같은 의미의 진행 표시를 또 두지 않아야 한다.
- 대화를 아래로 스크롤하면, 시스템은 단계 표시를 얇은 막대와 현재 단계 이름 한 줄로 줄여야 한다. 맨 위로 돌아오면 원래 크기로 돌아와야 한다.
- 타이머가 10초 이하로 남으면 원을 강조하고, 0초가 되면 맥박 효과와 함께 "찍었어요" 버튼을 보여 줘야 한다.
- 글꼴은 레포에 포함된 Pretendard를 써야 하고, 외부 CDN에 의존하지 않아야 한다.
- 신고 불가 결과와 빈 목록(신고 조회, 신고 사례)에는 남색 톤 일러스트를 보여 줘야 한다. 일러스트는 SVG 코드로 그리고 `aria-hidden`이어야 한다.

### 검증
- `npm run build`가 오류 없이 통과해야 한다.
- 390×844 크기로 모든 대상 화면의 스크린샷을 찍어 레퍼런스 톤과 비교해야 한다.
